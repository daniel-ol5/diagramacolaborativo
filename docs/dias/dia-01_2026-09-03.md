## 1. La idea del día, sin jerga

Hoy **no se construyó ninguna pantalla, ni un botón, ni nada que se vea bonito**. Y eso es exactamente lo que correspondía.

Pensá en el proyecto como un edificio que van a levantar cinco cuadrillas distintas al mismo tiempo: la del lienzo web, la del servidor, la del generador de código, la de la app móvil y la que exporta a Enterprise Architect. Todas van a trabajar sobre **el mismo diagrama**.

El problema es este: si la cuadrilla del lienzo cree que "una relación entre dos clases" tiene 8 datos, y la del generador cree que tiene 6, y la del XMI cree que la multiplicidad se escribe `"1..n"` en vez de `"1..*"`, entonces todo lo que construyan encima se va a caer, y se va a caer **tarde** — en la semana 3, cuando ya no haya tiempo.

Entonces hoy se hicieron dos cosas, y ninguna de las dos produce funcionalidad visible:

**1. Se escribió el diccionario del proyecto.** La definición exacta, en código Java, de qué es una clase, un atributo, un método, una relación, un paquete. Cuántos datos tiene cada uno, de qué tipo, y qué valor toman si no se especifican. A esto el plan lo llama *"congelar el modelo canónico"*: a partir de mañana, cambiar esa definición obliga a revisar el lienzo, el generador y el XMI **a la vez**. Por eso se hace el día 1 y no el día 10.

**2. Se probó si la cocina tiene gas antes de comprar el banquete.** La app móvil de la última fase tiene que entender español hablado **sin internet** (modo avión). Si eso no funciona en un celular real, se cae uno de los nueve requisitos del proyecto. Averiguarlo el 18 de septiembre sería fatal; averiguarlo hoy cuesta una tarde. Eso es el *spike*.

En una frase: **hoy se pusieron los cimientos y se comprobó que el terreno aguanta.**

Cualquiera que clone el repositorio puede compilar sin instalar nada más que Java.

**`HealthController`** — un endpoint de tres líneas:

```java
@GetMapping("/health")
public Map<String, String> health() {
    return Map.of("status", "UP", "service", "modelcollab-backend");
}
```

Responde `200` en `GET /api/v1/health`. Parece trivial y es de lo más importante del día: es lo que Docker consulta para saber si el contenedor arrancó bien, lo que Nginx en AWS va a usar para no mandar tráfico a un servidor caído, y lo que te dice en un segundo si el backend está vivo. **Todo sistema desplegado necesita un pulso.**

**`application.yml`** — la configuración. Dos decisiones que importan:

```yaml
url: ${SPRING_DATASOURCE_URL:jdbc:postgresql://localhost:5432/modelcollab}
```

Se lee como: *"usá la variable de entorno `SPRING_DATASOURCE_URL`; si no existe, usá esta dirección local"*. Gracias a eso **el mismo `.jar` compilado corre en tu PC contra el Postgres local y en AWS contra el Postgres del contenedor, sin recompilar y sin tocar una línea**. Es la diferencia entre un deploy de treinta segundos y una tarde de dolores.

```yaml
jpa.hibernate.ddl-auto: validate
```

Le prohíbe a Hibernate crear o modificar tablas. El dueño del esquema de la base de datos es **Flyway** (los archivos `.sql` versionados). Hibernate solamente *verifica* que las tablas coincidan con lo que el código espera, y si no coinciden se niega a arrancar. Sin esto habría dos fuentes de verdad compitiendo por la base, y en algún momento se pisan.

### 2.2 El modelo canónico (B-1) — el corazón del día

Trece archivos en `metamodel/model/`: **8 estructuras de datos + 5 enumerados**.

| Archivo | Qué representa |
| :--- | :--- |
| `CanonicalModel` | El diagrama completo (raíz) |
| `ClassEntity` | Una clase UML |
| `Attribute` | Un atributo de una clase |
| `Method` · `Parameter` | Un método y sus parámetros |
| `Relationship` | Una relación entre dos clases |
| `Package` | Una agrupación de clases |
| `Position` · `Waypoint` | Coordenadas en el lienzo |
| `Visibility` | `PUBLIC` `PACKAGE` `PROTECTED` `PRIVATE` |
| `AttributeType` | `INTEGER` `BIGINT` `VARCHAR` `TEXT` `DECIMAL` `BOOLEAN` `DATE` `DATETIME` `UUID` |
| `RelationshipType` | `ASSOCIATION` `AGGREGATION` `COMPOSITION` `INHERITANCE` `DEPENDENCY` `MANY_TO_MANY` |
| `OwningSide` · `Multiplicity` | Lado dueño de la relación y cardinalidades |

#### `record`: qué es y por qué

```java
public record ClassEntity(
        String id, String name, Visibility visibility, Boolean isAbstract,
        Position position, Double width, Double height,
        List<Attribute> attributes, List<Method> methods) { }
```

> **Sin jerga:** un `record` de Java 21 es una clase de datos que se declara en una sola línea. Java genera solo el constructor, los métodos de lectura, la comparación y el texto de depuración. Lo importante no es el ahorro de tipeo: es que **es inmutable** — una vez creada, una `ClassEntity` no se puede modificar. Para cambiarla hay que crear otra.

Eso último no es capricho. El requisito del proyecto es soportar **20 ingenieros editando el mismo diagrama a la vez**. Con objetos modificables, dos hilos tocando la misma clase al mismo tiempo producen corrupción de datos difícil de reproducir. Con objetos inmutables ese error **no puede ocurrir**, por construcción. Es la razón por la que §2.3 del plan arquitectónico exige `record` explícitamente.

#### El constructor compacto: donde viven los valores por defecto

Este es el mecanismo más fino del día:

```java
public Attribute {
    length    = length    == null ? DEFAULT_LENGTH    : length;    // 255
    precision = precision == null ? DEFAULT_PRECISION : precision; // 10
    scale     = scale     == null ? DEFAULT_SCALE     : scale;     // 2
    visibility   = visibility == null ? Visibility.PRIVATE : visibility;
    isPrimaryKey = isPrimaryKey != null && isPrimaryKey;   // por defecto false
    isNullable   = isNullable   == null || isNullable;     // por defecto true
    isUnique     = isUnique     != null && isUnique;       // por defecto false
}
```

> **Sin jerga:** el JSON Schema del plan dice cosas como *"si no se especifica la longitud de un `VARCHAR`, son 255 caracteres"*. Ese bloque es donde esa regla se cumple. Cuando llega un diagrama desde el navegador con un atributo al que le falta el campo `length`, **el dato se completa en el instante de entrar al sistema**, una sola vez. De ahí en adelante nadie más tiene que acordarse del valor por defecto: ni el generador de código, ni el exportador XMI, ni el validador.

La alternativa —dejar el campo vacío y que cada componente aplique el default por su cuenta— es exactamente cómo aparecen los bugs de *"en el lienzo se ve 255 pero el código generado dice 50"*.

#### Por qué `Integer` y no `int`

Detalle chico con consecuencia grande:

```java
Integer length,       // ✅ puede estar vacío (null)
Boolean isPrimaryKey  // ✅ puede estar vacío (null)
```

> **Sin jerga:** en Java, un `int` siempre tiene un valor (si no le ponés nada, vale 0), mientras que un `Integer` puede estar vacío. Necesitamos poder distinguir **"el JSON no traía este campo"** de **"el JSON traía explícitamente el valor 0"**. Con `int` esas dos situaciones se ven idénticas y sería imposible saber cuándo aplicar el valor por defecto. Por eso todo el modelo usa los tipos envueltos.

#### `Multiplicity`: el enumerado que no se puede escribir en Java

El schema exige que las cardinalidades se escriban `"0..1"`, `"1..1"`, `"0..*"`, `"1..*"`. Ninguno de esos textos es un nombre válido en Java (los puntos y el asterisco no se permiten). La solución:

```java
public enum Multiplicity {
    ZERO_ONE("0..1"), ONE_ONE("1..1"), ZERO_MANY("0..*"), ONE_MANY("1..*");

    @JsonValue   public String getValue() { return value; }              // cómo se ESCRIBE en JSON
    @JsonCreator public static Multiplicity fromValue(String v) { ... }  // cómo se LEE desde JSON

    public boolean isCollection() { return this == ZERO_MANY || this == ONE_MANY; }
}
```

> **Sin jerga:** el nombre interno y el nombre externo se separan. En el código Java se llama `ZERO_MANY`; cuando viaja por la red o se guarda en la base, se escribe `"0..*"`. `@JsonValue` y `@JsonCreator` son las dos etiquetas que hacen esa traducción automáticamente, en ambos sentidos.

`isCollection()` parece un extra, pero es el que el generador va a usar el día 8: si la multiplicidad es de colección, el atributo Java generado es una `List<>` con anotación `@OneToMany`; si no, es un objeto suelto con `@ManyToOne`.

**Nota de nomenclatura:** la clase se llama `ClassEntity` y no `Class` porque `java.lang.Class` ya existe en Java y usar ese nombre sería una fuente permanente de confusión.

#### `JacksonConfig`: un solo traductor para todo el sistema

Jackson es la librería que convierte JSON ↔ objetos Java. Acá se configura **uno solo, compartido por todo el sistema**:

```java
.enable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES)
.serializationInclusion(JsonInclude.Include.NON_NULL)
```

> **Sin jerga:** la primera línea dice *"si llega un campo que no está en el diccionario, fallá con error en vez de ignorarlo"*. Suena hostil, y es a propósito: **ese es el candado que mantiene congelado el contrato**. Si alguien —o la IA de Gemini en la Fase 4— inventa un campo que el schema no define, el sistema lo grita en el acto en vez de tragárselo y perder el dato en silencio. La segunda línea dice *"no escribas los campos vacíos"*, para que el JSON que viaja por WebSocket sea lo más liviano posible; con 20 usuarios y mensajes constantes, eso es ancho de banda real.

El comentario del propio archivo lo resume mejor que yo: *"si dos capas usan mappers distintos, el contrato de §7 deja de estar congelado"*.

## 3. Móvil — el spike de voz offline (B-2)

Carpeta: `spike-voz/` · Sesión: `[cl2]`

### 3.1 Qué se está probando exactamente

Una sola pregunta, con respuesta de sí o no: **¿un celular Android real transcribe español hablado con el modo avión activado?**

No se está construyendo la app móvil. Se está construyendo un **instrumento de medición**, que se usa una vez y decide en qué tecnología se escribe toda la Fase 5 (18 al 20 de septiembre).

### 3.2 Decisión: Flutter primero, no React Native

El plan pone React Native como ruta principal. Se invirtió el orden, y el motivo es de tiempo, no de gusto: la ruta React Native exige compilar un *Custom Dev Client* con EAS Build — cuenta de Expo, compilación en servidores remotos, **20 a 40 minutos por intento**. Flutter ya está instalado en esta máquina y llega a la misma evidencia con un `flutter run` de dos minutos.

Lo que B-2 tiene que responder no es *"qué framework es mejor"*, es *"hay texto en pantalla en modo avión"*. Si Flutter falla, se corre React Native habiendo perdido una hora, no un día. La decisión queda registrada como **D-02** en la bitácora.

### 3.3 Lo que se implementó

**Dependencias** (`pubspec.yaml`):

| Paquete | Para qué |
| :--- | :--- |
| `speech_to_text ^7.4.0` | El reconocimiento de voz — el objeto de la prueba |
| `connectivity_plus ^7.3.1` | Detectar el estado de la red **y mostrarlo en pantalla** |
| `permission_handler ^13.0.1` | Pedir el permiso de micrófono |

`connectivity_plus` no es decorativo: hace que **la captura de pantalla se pruebe a sí misma**. Sin un indicador de red visible, una foto del texto transcrito no demuestra nada — cualquiera podría objetar que había wifi.

**El permiso invisible que rompe todo** (`AndroidManifest.xml`):

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO"/>

<queries>
    <!-- Android 11+ (API 30): sin esto el reconocedor de voz no se resuelve -->
    <intent><action android:name="android.speech.RecognitionService"/></intent>
    <package android:name="com.google.android.googlequicksearchbox"/>
</queries>
```

> **Sin jerga:** desde Android 11, una app **no puede ni siquiera ver** qué otras apps hay instaladas en el teléfono, salvo que declare específicamente cuáles necesita. El motor de reconocimiento de voz es una app aparte (la de Google). Si no está ese bloque `<queries>`, la app ni se entera de que el reconocedor existe: `initialize()` devuelve `false` **sin ningún mensaje de error**. Es una de las fallas silenciosas más frustrantes de Android, y es la razón número uno por la que estos spikes "no funcionan" sin motivo aparente.

**El diagnóstico de idioma** (`main.dart`):

```dart
final locales = await _speech.locales();
final es = locales.where((l) => l.localeId.toLowerCase().startsWith('es')).toList();
resumenEs = es.isEmpty
    ? 'NINGUNO (falta el paquete de español)'
    : es.map((l) => l.localeId).join(', ');
```

> **Sin jerga:** antes de intentar nada, la app le pregunta al teléfono *"¿qué idiomas sabés reconocer?"* y filtra los que empiezan con "es". Si la lista vuelve vacía, el mensaje en pantalla es literalmente **"NINGUNO (falta el paquete de español)"** — que es el diagnóstico exacto, en vez de un fallo genérico. Después elige el mejor disponible por orden de preferencia: `es_BO`, `es_MX`, `es_ES`.

**La línea que define el spike:**

```dart
await _speech.listen(
  listenOptions: SpeechListenOptions(
    onDevice: true,                    // ← ESTA
    listenMode: ListenMode.dictation,
    localeId: _localeElegido,
    listenFor: Duration(seconds: 30),
    pauseFor: Duration(seconds: 4),
  ),
);
```

> **Sin jerga:** `onDevice: true` le exige al sistema **procesar la voz dentro del teléfono, sin mandar el audio a los servidores de Google**. Es literalmente la pregunta del spike convertida en una línea de código. `ListenMode.dictation` le indica que espere una frase larga y no una orden corta; `pauseFor: 4s`, que no corte al primer silencio breve.

**La pantalla como evidencia.** La interfaz es deliberadamente fea, y el comentario del archivo lo dice: *"La UI es fea a propósito: está diseñada para que UNA captura de pantalla sirva como evidencia"*. Muestra a la vez el estado de la red, si el reconocedor declaró soporte en dispositivo, el locale elegido, la frase exacta a dictar, el texto transcrito, la latencia medida y una bitácora con marcas de tiempo. Una sola foto contiene toda la prueba, sin necesidad de creerle a nadie.

### 3.4 Lo que se corrió — y lo que todavía no

**Dispositivo:** Xiaomi Mi 11T Pro (M2012K11AG), Android 13, API 33.

Llegar a instalar la app costó tres bloqueos encadenados, todos de MIUI y todos resueltos por Daniel a mano:

1. Dispositivo en estado `unauthorized` → aceptar la huella RSA.
2. `INSTALL_FAILED_USER_RESTRICTED` → activar *"Instalar vía USB"* en Opciones de desarrollador. **MIUI exige cuenta Mi con internet para ese toggle**, así que este paso y la descarga del paquete de idioma van obligatoriamente antes del modo avión.
3. `adb shell input tap` bloqueado con `SecurityException` (`INJECT_EVENTS`) → **no se puede automatizar la prueba**; cada dictado depende de que una persona opere el teléfono.

**Corrida baseline (con red) — ✅ ejecutada.** Es la corrida de contraste, deliberadamente con las dos condiciones al revés:

| Campo | Valor |
| :--- | :--- |
| `initialize()` | `true` |
| `onDevice` pedido | `false` |
| locales `es` | `es_ES`, `es_US` |
| conectividad | wifi (banner rojo: *"HAY RED — EL SPIKE NO VALE"*) |
| texto transcrito | *"agenda una cita para mañana a las 10"* |
| latencia | 4498 ms |

Lo que demuestra: la cadena completa funciona —instalación, permisos, `<queries>`, inicialización, resolución del locale español, micrófono y transcripción en pantalla—. Elimina de golpe una familia entera de fallas posibles. **Lo que no demuestra: absolutamente nada sobre el funcionamiento offline**, que es la única pregunta del spike. La propia app lo declara en rojo.

**Corrida decisiva (modo avión + `onDevice: true`) — 🟡 pendiente**, esperando que Daniel opere el teléfono.

Si falla con `onDevice` en ON, se repite con el interruptor en OFF pero siempre en modo avión. Esa segunda corrida separa dos diagnósticos que se parecen y significan cosas opuestas: *"no hay modelo de español descargado"* (error del reconocedor, se arregla bajando el paquete) contra *"no reconoce nada sin nube"* (error de red, manda a la Ruta C con Vosk y suma un día al cronograma).

> **Nota:** que `locales()` liste `es_ES` **no prueba** que el modelo offline esté descargado — solo que el reconocedor conoce el idioma. El proveedor configurado es *Speech Services by Google*, que es donde viven los paquetes offline, pero **si el modelo está bajado no se puede leer desde `adb` sin root**. La prueba empírica es la única forma de saberlo; por eso el dictado en modo avión *es* el experimento.

### 3.5 Un hallazgo fuera de alcance que sirve para la Fase 5

Se dictó *"a las **diez**"* y el reconocedor devolvió *"a las **10**"*, en dígitos. **El motor normaliza los numerales por su cuenta.** El `SlotExtractor` del día 19 tiene que aceptar las dos formas y no asumir que los números llegan como palabras. No estaba en el alcance del spike, y es exactamente el tipo de detalle que solo aparece probando en hardware real.

## 4. Cómo encaja todo esto con lo que viene

El trabajo de hoy no se ve, pero es de lo que cuelga literalmente todo el resto:

```
   Los records de HOY  ─────────────────────────────────────┐
          │                                                 │
          ├─→ Día 4-5   se guardan como JSONB en PostgreSQL │
          ├─→ Día 6-7   el lienzo React dibuja cada uno     │
          ├─→ Día 8     viajan por WebSocket entre navegadores
          ├─→ Día 11    las plantillas FreeMarker los leen y escupen Java compilable
          ├─→ Día 13    el exportador los traduce a XMI para Enterprise Architect
          └─→ Día 18    de ellos se deriva el intents.json de la app móvil…
                                                            │
   El motor de voz de HOY ──────────────────────────────────┘
          └─→ Día 19    …que esa app usa para entenderte en modo avión
```

Los **3 diagramas de referencia** (barbería, veterinaria, inventario) que se están escribiendo hoy son los datos de prueba de cada una de esas flechas. Y el **test de round-trip** —leer el JSON, convertirlo a Java, volverlo a convertir a JSON y verificar que salga idéntico— es lo que demuestra que en ese viaje de ida y vuelta no se pierde ni un campo. Ese test es el criterio de aceptación de B-1: mientras esté en verde, el contrato está congelado.

### Fallos documentados (valen para la defensa)

- **`evidencia.sh` estuvo a un commit de producir evidencia falsa.** El script escribía el archivo `spike-voz-modo-avion.png` **sin comprobar que el modo avión estuviera activo**, y una corrida de pre-chequeo generó un archivo con ese nombre teniendo el Wi-Fi encendido. Delante de un tribunal eso no es un descuido, es una captura que afirma algo que no ocurrió. Corregido: el script solo usa ese nombre si `settings get global airplane_mode_on` devuelve `1`; si no, guarda como baseline. **Una corrida de contraste ya no puede colarse como evidencia decisiva.**
- `permission_handler 13.0.1` **removido**: su artefacto Android 14.0.0 usa la DSL `kotlin { compilerOptions { jvmTarget } }`, incompatible con el Kotlin Gradle Plugin del template de Flutter 3.41.5 (5 errores de compilación del script Gradle). Resulta innecesario: `initialize()` de `speech_to_text` ya solicita `RECORD_AUDIO` por su cuenta.
- **Sin test de contexto Spring** (`@SpringBootTest`): exigiría un PostgreSQL en CI. Los tests de hoy son puros de Jackson y no tocan la base, a propósito.
- **Trampa para el `MetamodelValidator` del día 10:** la condición del caso 3 de D-08 no es *"los dos extremos son iguales"* sino *"los dos extremos son **escalares** e iguales"*. Un `MANY_TO_MANY` `0..* ↔ 0..*` también tiene los extremos iguales, así que la condición ingenua haría que el validador emitiera una advertencia sobre **todas** las relaciones muchos-a-muchos. Detectado al escribir el test de simetría, que contaba 3 relaciones donde debía contar 2.
